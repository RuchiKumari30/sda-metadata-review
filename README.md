## Setup and Execution

### 1. Prerequisites
Ensure you have Python 3.9+ installed.

### 2. Install Dependencies
Open your terminal/command prompt, navigate to the `sda-metadata-review` directory, and run:
```bash
pip install -r requirements.txt
```

### 3. Run Data Processing Scripts
Run the scripts in the following order to generate the processed data:

**Step 1: Quality Review**
```bash
python src/quality_review.py
```
*This reads the raw CSV files and generates `quality_flags.csv`, `clean_submissions.csv`, and `review_summary.txt` in the `data/processed/` folder.*

**Step 2: Compliance Analysis**
```bash
python src/compliance_analysis.py
```
*This uses the processed flags and raw tracker to generate `compliance_report.csv` and `dpdp_detail.csv`, outputting summary tables to the console.*

### 4. Run Dashboard Locally
To view the interactive dashboard on your local machine:
```bash
streamlit run src/dashboard.py
```
*This will open the dashboard in your default web browser (usually at http://localhost:8501).*

## Methodology and Assumptions

### Ambiguous Data Quality Decisions
* **Date Formats:** The standard is YYYY-MM-DD. When parsing `submitted_on` for the dashboard timeline, I noticed some entries used `MM/DD/YYYY` (e.g., META-015). I flagged these as invalid in the quality review but built the dashboard to attempt parsing both formats so the data could still be visualized.
* **Missing Record Counts:** A blank `record_count` was flagged as an error unless the `formats` column contained "API", assuming APIs stream data and don't have a static record count.
* **Compliance Cross-Checking:** The `compliance_tracker.csv` contained trailing whitespace in some fields (like `final_status`), which was stripped during processing to ensure accurate matching against flagged submissions.

### Assumptions
* Missing or NaN values in the CSV were treated as empty strings for consistent validation.
* "Valid positive integer" for record count means strictly > 0.
* For the aging analysis (calculating follow-up wait times), the "current" date was assumed to be **25 April 2026**, as specified in the assignment brief.
* A dataset was considered "fully DPDP compliant" only if both the classification was Restricted/Confidential AND a Data Steward was explicitly assigned.

## Future Improvements

With more time, I would improve the following:
1. **Automated Alerts:** Integrate an email API (like SendGrid) to automatically draft and send follow-up emails for pending submissions based on the generated flags.
2. **Dashboard Interactivity:** Add a detailed view in the dashboard where the Data Governance Lead can click on a specific department to see the exact issues holding up their pending submissions.
3. **Fuzzy Matching:** Implement fuzzy matching to detect typos in department names or data classifications to prevent valid submissions from being incorrectly flagged.
4. **Historical Trend Analysis:** If historical data were available, track the average time taken by each department to resolve issues from 'Pending' to 'Approved'.
